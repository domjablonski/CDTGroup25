PART 10 - KNOWN BUGS AND FIXES
=====================================================================

ast.literal_eval is slow               -> cleaning takes ~1 min: run it once, load the Parquet files.
Parquet list column comes back as an   -> cleaning.load_recipes() converts back to lists.
  ndarray ("truth value is ambiguous")
None becomes NaN in a str column       -> pandas 3: test with pd.isna(...), not "is None".
calorie_level is Int8 with <NA>        -> drop NA before scikit-learn; never fill it.
MemoryError on all pairs               -> never n^2 pairs: LSH buckets; scipy.sparse for exact
                                          Jaccard on the 5,000-recipe sample only.
Python's hash() differs between runs   -> lsh.stable_hash (CRC32).
NumPy uint32 overflow in (a*x + b) % p -> compute in int64/uint64 with p = 2^31 - 1.
PCY buckets use too much RAM           -> np.int32 array, n_buckets <= 1e7 (~40 MB).
PCY != A-Priori on a few pairs         -> bitmap threshold must be >= the support count, and pass 2
                                          must require BOTH items frequent AND the bucket frequent.
mlxtend apriori needs one-hot data     -> TransactionEncoder on the 1 % sample only.
PMI of a pair seen once is huge        -> only frequent pairs (PAIRS) get a weight; prefer NPMI.
Negative PMI as an edge weight         -> keep positive associations only (weight >= min_weight > 0).
Louvain changes between runs           -> seed=config.SEED; report the mean over 5 seeds.
SpectralClustering "not connected"     -> largest connected component; say so.
kNN accuracy suspiciously high         -> leakage: a test recipe voted by its copy or by test
                                          neighbours. Check the split and the train-only filter.
FileNotFoundError data/processed/...    -> run `python -m foodcom.cleaning` from the repo root.
ModuleNotFoundError: foodcom            -> `pip install -e .` in the active venv.
Notebook uses an old module version    -> restart the kernel (or %autoreload 2).
